# Midnight Memory — Provenance & Evidence Authority (v1.1.0)

Implemented in `src/engine/authority.ts`, enforced by `src/engine/validation.ts`
at write time. Contract version: **1.1.0** (additive).

## Principle

A memory claim traces to its source: a user note, a verified Study finding,
Performance evidence, Analysis evidence, a Search session, repository
evidence, or another source kind. **Authority is structural, not textual** —
a summary generated by an agent cannot become authoritative solely because
it is fluent.

## Source kinds → authority tiers

| SourceKind | Tier |
|---|---|
| `study_finding`, `performance_evidence`, `repository_evidence` | `verified_source` |
| `user_decision` (explicit user-authored decision, Task 32) | `user_decision` — the user's STRONGEST subjective authority within their declared scope |
| `user_note` | `user_reported` |
| `analysis_evidence`, `search_session`, `external_document` | `analysis` |
| `agent_summary`, `agent_inference` | `agent_derived` (capped) |
| `unknown` | `unattributed` (capped) |

The tier is refined by epistemic honesty caps: `inferred` / `recommendation`
claims are capped regardless of source kind. Assessment is exposed via
`MemoryEngine.explainAuthority(recordId)` and `memory.explain`.

## Write-time enforcement (before persistence)

1. `epistemicClass: "observed"` **requires ≥ 1 evidence reference** —
   observation means the claim traces to source evidence.
2. `observed` **cannot** be grounded by `agent_summary` / `agent_inference`
   / `unknown` — agent output is never authoritative as observation, no
   matter how fluent, confident, or well-evidenced its narration is.
3. `sourceKind: "agent_summary"` **requires** `provenance.derivedFrom` — a
   summary must point at what it summarizes.

Violations raise `MEMORY_VALIDATION_FAILED` with messages naming the rule.

## Provenance shape (per record)

```json
{
  "actor":  { "kind": "human|agent|engine|tool", "name": "…", "agentType": "…" },
  "method": "extracted | summarized | decided | …",
  "capturedAt": "2026-08-30T…Z",
  "sourceKind": "study_finding",
  "derivedFrom": { "engine": "study_document", "ref": "doc:study-9" }
}
```

`sourceKind` defaults to `"unknown"` when omitted (→ `unattributed`, capped).
Pre-1.1 records are backfilled to `"unknown"` by migration 4 — they read as
capped, never as fabricated authority.

## Agent neutrality

Actors remain generic; no agent product is recognized or privileged. The
model distinguishes roles (agent vs human vs engine vs tool) only through
declared source kinds — which the *caller* must declare honestly and which
the engine structurally caps when they are agent-derived.
