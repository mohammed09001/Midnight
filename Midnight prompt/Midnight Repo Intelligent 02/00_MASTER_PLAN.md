# MIDNIGHT REPO INTELLIGENT 02 — MASTER PLAN

## Consolidation, Intelligent Gap Closure, and LLM Cost Reduction

**Product:** Midnight Repo Intelligent  
**Parent:** Midnight Performance  
**Companion:** Midnight Memory  
**Phase:** 02  
**Mode:** repair + consolidation + measurable intelligence upgrade  
**Target harness:** provider-neutral repository-capable coding agent  

## Mission

Repo Intelligent 02 exists to close the gaps left by Repo Intelligent 01 **without turning the codebase into a larger collection of disconnected engines**.

The goal is one coherent production runtime:

`Performance evidence -> learning pressure -> internal sufficiency -> cheapest qualified resolver -> optional external research -> evidence synthesis -> attention decision -> exposure -> outcome -> learning`

02 must reduce avoidable LLM cost by moving more decisions into deterministic computation, caching, local retrieval, lightweight machine learning, and learned routing. It must never reduce cost by silently lowering correctness.

## Repository reality that motivated 02

Before implementation, the coding agent must re-inspect current repository state and prove whether each gap still exists. Do not trust this document over the repository.

Known gaps to investigate and close:

- the canonical `run_pipeline` path does not yet prove that every Repo Intelligent engine participates in one production decision flow;
- `ContinuousLearningLoop` exists but is not yet proven to be the durable runtime scheduler that drives the canonical pipeline;
- Memory sufficiency is not demonstrated as a true per-question `ABSENT / PARTIAL / SUFFICIENT` decision;
- a Memory-sufficiency qualification can pass for the wrong reason when privacy already blocks export;
- production external discovery/fetch/embedding/model providers are not fully wired;
- the Repo Intelligent repository adapter does not consistently exploit Performance's deepest symbol/region-level resolution;
- the newer attention formula can coexist with an older terminal-priority formula, creating duplicate ranking ownership;
- cost-quality routing, federated retrieval, observability, Performance fusion, analogy, and attention are implemented more strongly as separate modules than as one canonical runtime;
- Performance evidence reads need explicit coverage/pagination semantics rather than an unproven fixed bounded slice;
- integrated qualification must cover Performance + Memory + Repo Intelligent + Desktop together.

## Frozen ownership boundaries

- **Performance** owns canonical development-history evidence and Performance projections.
- **Repository** owns current source-code truth.
- **Memory** owns durable promoted knowledge.
- **Repo Intelligent** owns derived project intelligence, research jobs, graph overlays, exposures/outcomes, bounded caches, and optional learned-routing state.
- No direct sibling database access.
- No duplicate Memory authority.
- No ML model may change epistemic claim strength.
- No external source is trusted instructions.
- No coding-agent provider is privileged in the architecture.

## Intelligence ladder

Every decision must attempt the cheapest qualified rung first unless policy or task requirements justify skipping upward:

1. deterministic local computation;
2. exact/content-addressed cache;
3. lexical and structural retrieval;
4. local graph traversal;
5. lightweight CPU ML/statistical decision model;
6. semantic retrieval/embeddings only when needed;
7. small/cheap LLM for unresolved classification or bounded transformation;
8. strong LLM for synthesis/reasoning only when expected value justifies it;
9. abstain/defer when confidence remains insufficient.

The learned layer is a **router and estimator**, not a replacement for source truth.

## Research basis

Use these as research directions, not copy-paste architecture:

- **RouteLLM (arXiv:2406.18665):** learned strong-vs-weak model routing can reduce cost while preserving response quality.
- **FrugalGPT (arXiv:2305.05176):** model cascades can escalate only when cheaper stages are insufficient.
- **BARGAIN (arXiv:2509.02896):** cost reduction should be constrained by measured statistical quality guarantees, not naive confidence alone.
- **Online Multi-LLM Selection via Contextual Bandits (arXiv:2506.17670):** online contextual routing can adapt model choice under changing task context without requiring offline fine-tuning.
- **Cost-sensitive learning-to-defer research:** automated decisions should be allowed to abstain and escalate rather than fabricate confidence.
- **River online-ML ecosystem:** useful optional reference for incremental classifiers, bandits, model selection, progressive evaluation, and drift detection.

Do not introduce a neural network merely because this phase mentions machine learning. Prefer the simplest model class that yields measured benefit.

## Data flywheel without a new data authority

Learn only from bounded feature/outcome records that reference canonical evidence.

Allowed learned-decision record fields include:

- project-scoped feature snapshot;
- decision type;
- router/model version;
- chosen rung/provider/model;
- confidence/uncertainty;
- cost and latency;
- verification result;
- later outcome association;
- exposure feedback where applicable;
- Performance/Memory evidence references;
- privacy decision;
- counterfactual availability state when measurable.

Do not duplicate raw source code, prompts, transcripts, or complete Memory records into a new ML store by default.

## Cold-start and safety policy

No learned router controls production at cold start.

Required progression:

`deterministic baseline -> shadow predictions -> offline replay -> calibration -> bounded canary -> monitored online learning -> drift detection -> rollback`

Every learned model must have:

- feature-schema version;
- model/version identity;
- minimum training-sample rule;
- calibration evidence;
- abstention range;
- deterministic fallback;
- rollback mechanism;
- drift/staleness status;
- per-project privacy scope.

## Repair discipline

Prefer this order when a capability already exists:

`reuse -> connect -> simplify -> replace -> delete duplicate -> add only what is missing`

Do not stack a second implementation beside an existing one to avoid refactoring.

For every material requirement, produce:

`requirement -> canonical owner -> current implementation -> defect -> chosen repair -> verification evidence`

## Final economics metric

Primary release metric:

`useful_project_learning / (user_attention_cost + normalized_compute_cost + avoidable_network_cost)`

Quality floors are constraints, not variables to sacrifice.

Track at minimum:

- deterministic resolution rate;
- exact/cache reuse rate;
- local retrieval resolution rate;
- ML accept/abstain/escalate rate;
- external-research rate;
- small-model and strong-model invocation rates;
- cost per qualified insight;
- latency by stage;
- false suppression and false escalation;
- attention cost;
- drift events;
- later outcome associations.

## Repo Intelligent 02 definition of done

02 is complete only when a fresh-checkout qualification proves:

- one canonical runtime owns the stage sequence;
- Memory can genuinely stop unnecessary external work through a per-question sufficiency decision;
- external research works through real provider-neutral adapters when allowed and needed;
- external content remains inert untrusted evidence;
- symbol/region-level project references are used when Performance can provide them;
- one attention authority and one escalation/routing authority remain;
- deterministic/cache/local/ML/LLM rungs are measurable and can abstain/escalate;
- learned routing is optional and deleting its state does not break correctness;
- Performance pagination/coverage is explicit;
- continuous learning has durable bounded scheduling/checkpoints if the product claims continuous operation;
- cross-project privacy isolation is proven;
- Performance, Memory, Repo Intelligent, and Desktop tests are integrated into qualification;
- cost/latency improvement is measured at preserved quality, or the final report states `NO VERIFIED ECONOMIC BENEFIT YET`.

Never report completion from architectural intent or unit-test count alone.
