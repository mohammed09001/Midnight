## Performance must be the temporal nervous system

When Repo Intelligent reasons about project behavior over time, reuse canonical Performance semantics rather than re-deriving them from raw Git or copied transcripts.

At minimum preserve/reuse where relevant:

- recurrence and historical matching;
- unusualness/anomaly semantics where `unusual != bad`;
- recommendation and later outcome semantics;
- provider/model cost/usefulness accounting;
- repository-change and verification evidence;
- project/component/task history.

Every proactive insight must retain a Performance lineage receipt or an explicit reason that no Performance evidence was applicable.

## Deeper entity resolution

Wire the deepest stable entity references Performance currently supports for the question at hand.

Prefer:

`region/symbol -> file -> module/package -> repository`

when evidence exists.

Do not fake symbol identity across moves/renames. Preserve uncertainty and fallback references when continuity cannot be proven.

## Federated retrieval as one planner

Internal retrieval must plan across:

- current repository truth;
- Performance evidence/projections;
- Memory durable knowledge;
- Repo Intelligent graph projections/caches;
- external evidence only after internal-gap and policy gates.

The planner must record:

- sources queried;
- query purpose;
- coverage;
- freshness;
- contradictions;
- stop reason;
- cost.

Do not run every source indiscriminately.

## Analogy qualification

Structural analogy must require explicit comparable dimensions, for example:

- component role;
- dependency shape;
- failure/friction pattern;
- architectural constraint;
- change trajectory;
- verification behavior;
- temporal phase.

Reject keyword-only similarity.

Analogy is advisory evidence. It cannot overwrite current-project facts.

## One attention authority

There must be one production ranking formula/owner.

Use the Repo Intelligent 01 attention concept as the starting contract:

`learning_pressure × evidence_strength × novelty × expected_learning_value × timing_fit - (redundancy + interruption_cost + uncertainty + stale_risk)`

If current repository evidence proves a better calibrated formula is already canonical, preserve it and document why. Otherwise migrate the terminal path to the attention engine and delete/deprecate the competing old terminal priority formula.

Do not sum a second independent priority score after attention ranking.

## ML interaction

Lightweight learned estimates may supply bounded inputs such as expected learning value, timing fit, novelty probability, or interruption risk only when qualified.

Hard constraints remain deterministic:

- privacy;
- project authorization;
- provenance requirements;
- stale/contradiction exclusions;
- attention budget ceilings.

An uncertain ML estimate must lower confidence or abstain rather than fabricate ranking precision.

## Attention budget

Maintain a rolling project/user attention budget.

The system should suppress low-value repeated cards even when compute cost is cheap.

Record:

- candidate score components;
- reason shown/suppressed;
- previous exposure similarity;
- attention budget before/after;
- later outcome/feedback if available.

## Query/read surfaces

Ensure query APIs expose explanations derived from the same canonical decision path, including:

- why this topic now;
- Performance evidence behind pressure;
- internal knowledge sufficiency;
- retrieval path;
- external research reason;
- analogy evidence;
- attention score components;
- cost-quality route;
- later outcome.

Do not rebuild a separate explanation model in the UI/query layer.

## Verification

Prove:

- terminal exposure uses the same attention authority as API explanations;
- old competing priority owner is removed/deprecated;
- federated retrieval skips irrelevant sources and records stop reasons;
- Performance history affects decisions through canonical projections rather than duplicate raw-history reconstruction;
- symbol-level lineage is used when available and falls back honestly when not;
- keyword-only analogy is rejected;
- stale/contradicted analogy cannot silently dominate ranking;
- repeated low-value exposure is suppressed by attention budget;
- ML disabled -> deterministic ranking remains functional.
